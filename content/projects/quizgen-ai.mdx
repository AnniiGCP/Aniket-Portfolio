## Introduction

**QuizGenAI** is an adaptive, dynamic assessment and automated evaluation platform designed to generate concept-calibrated quizzes from technical source materials, curriculum syllabi, and documentation.

Unlike basic LLM prompting demos that break on unstructured text responses, QuizGenAI enforces strict, validated JSON response contracts from language models. Every generated question, distractor, explanation, and difficulty level strictly conforms to authoritative Pydantic schemas before database persistence.

## Why I built it

In academic and developer hiring environments, educators and recruiters spend dozens of hours manually writing technical quizzes. While LLMs can generate questions quickly, raw model output frequently hallucinates malformed choices, forgets correct answer keys, or produces inconsistent formatting that crashes frontend assessment interfaces.

During the HIRE-4-THON Hackathon, our team designed QuizGenAI to solve this reliability problem: an API-first quiz engine with strict boundary validation, timed exam workflows, and developer streak visualization.

## Core features

- **Contract-first API architecture:** All generative payloads and client requests are validated at the network boundary using Pydantic v2 models.
- **Dynamic quiz generation:** Generate multiple-choice assessments tailored to specific technologies, concepts, and difficulty thresholds.
- **Timed assessment engine:** Client-side countdown timers with auto-submission triggers and anti-tamper client state guards.
- **Immediate explanatory feedback:** Instant post-exam score breakdowns with concept-by-concept explanations for incorrect answers.
- **Developer activity streak visualizer:** GitHub-style contribution heatmap tracking daily practice consistency and topic mastery.
- **Relational data persistence:** Backed by SQLAlchemy ORM with SQLite for rapid local development and seamless PostgreSQL production readiness.

## How it works

1. **Topic and difficulty selection:** An instructor or student specifies a technology (e.g. Python AsyncIO, Docker Networking), difficulty tier, and question count.
2. **Constrained generation prompt:** The FastAPI backend constructs a structured prompt specifying strict JSON-mode response criteria.
3. **Pydantic schema validation:** The LLM's response is parsed against the `QuizSchema` model. If a field or type violation is detected, an automatic validation retry repairs the output.
4. **Database persistence:** Validated questions and metadata are committed to the relational database with unique session identifiers.
5. **Timed exam delivery:** The student completes the quiz within the enforced time limit.
6. **Scoring & streak recording:** On submission, the backend grades responses, computes the score percentage, records the attempt in the user's activity streak ledger, and returns the explanatory review.

## System architecture

QuizGenAI follows clean architecture separation:
- **Presentation layer:** Responsive React application built with TypeScript and Tailwind CSS, featuring timed exam views, score cards, and activity grids.
- **Backend service:** High-performance asynchronous FastAPI service running on Uvicorn, handling question generation, evaluation, and user progress endpoints.
- **Validation layer:** Pydantic v2 schemas guaranteeing end-to-end type safety between the LLM, database, and client interface.
- **Data storage:** Relational persistence handled by SQLAlchemy ORM with SQLite, with full Alembic migration support for production database provisioning.

## Engineering challenges

### Guaranteeing valid quiz schemas under pressure
LLMs can occasionally output markdown code blocks or invalid JSON syntax. We implemented a resilient backend coercion pipeline that strips markdown delimiters, verifies required schema keys, and re-prompts the model with explicit error tracebacks if validation fails.

### Synchronizing client timers with backend submission deadlines
To prevent browser-based timer manipulation during exams, the backend stores the official start timestamp and validates that submissions arrive within the allowed time delta plus a minor network grace window.
